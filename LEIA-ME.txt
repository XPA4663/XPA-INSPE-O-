XPA · Inspeções e Manutenção — aplicativo único (PWA offline)

Módulos incluídos nesta versão (8):
  🌡️ Inspeção termográfica (NETA Tab. 100.18)
  🏭 Manutenção preventiva de subestação (AT/MT/BT, proteção, aterramento, civil – com ensaios)
  👁️ Inspeção visual de subestação (mesmos checklists, sem ensaios)
  🔋 Inspeção de grupo gerador (motor, alternador, QTA; isolamento IP/DAR, ôhmica, teste em carga)
  ⚙️ Inspeção de motores elétricos (isolamento, ôhmica, corrente, temperatura, vibração)
  🌩️ Laudo de SPDA (NBR 5419 – captação, descidas, aterramento, DPS; resistência e continuidade)
  🦺 Laudo / auditoria NR-10 (prontuário, medidas de controle, instalações, EPI/EPC, emergência)
  🧰 Visita técnica (constatações por item, fotos, prioridade, recomendações para proposta)

Publicar no GitHub Pages:

 2. "uploading an existing file" > selecione os 14 arquivos > Commit changes.
 3. Settings > Pages > Source: "Deploy from a branch" > Branch: main / (root) > Save.
 4. Aguarde 1–2 min. Endereço: https://SEU-USUARIO.github.io/XPA-INSPECOES/

Instalar no celular (com internet, só na primeira vez):
 - Android (Chrome): abra o endereço > menu ⋮ > "Instalar app" / "Adicionar à tela inicial".
 - iPhone (Safari): abra o endereço > Compartilhar > "Adicionar à Tela de Início".
 - Abra o app instalado uma vez com internet e espere ~10 s (baixa os geradores de PDF/Excel).

Migrar os dados dos apps antigos (XPA-TERMOGRAGIA e XPA-SUBESTACAO):
 - No app antigo, abra cada inspeção > "Exportar backup" (arquivo .json).
 - No app novo, tela inicial > "Importar backup" > escolha o .json. Ele é convertido automaticamente.

Estrutura: index.html = núcleo (telas, armazenamento, fotos, backup, kits de PDF/Excel);
mod-checklist.js = fábrica dos módulos de checklist; cada mod-xxx.js = um tipo de trabalho.
Adicionar um módulo novo: criar mod-xxx.js, incluir <script src="mod-xxx.js"> no index.html
e acrescentar './mod-xxx.js' na lista LOCAL do sw.js. Atualizar: mudar VERSION em sw.js.

Importante: os dados ficam no aparelho. Use "Exportar backup" ao final de cada visita.

PASSO 1 – Regras do Firestore (obrigatório para o módulo funcionar)
 - Firebase Console > Firestore Database > Regras > substitua pelo conteúdo de firestore.rules > Publicar.
 - ATENÇÃO: o bloco "match /data/users/{uid}/{docId}" reproduz o acesso dos trabalhos de inspeção
   (cada usuário só vê os seus). Se as suas regras atuais tiverem algo a mais, mantenha junto.

PASSO 2 – Publicar o app (GitHub)

 - Entre com xavier@xpaengenharia.com.br > cartão Propostas > "Acessos" > cadastre os e-mails autorizados
   e confira o "Último número usado" (58 = próxima será 10_26059).

PASSO 3 – Análise por IA (opcional; sem ela a leitura local de .docx continua funcionando)
 - Requer o plano Blaze no Firebase e uma chave da API da Anthropic (console.anthropic.com).
 - No computador, com Node 20 instalado, na pasta do repositório:
     npm install -g firebase-tools
     firebase login
     cd functions && npm install && cd ..
     firebase functions:secrets:set ANTHROPIC_API_KEY      (cole a chave quando pedir)
     firebase deploy --only functions,firestore:rules
 - Custo: cobrado por uso na conta da Anthropic (algumas dezenas de centavos por documento).
   O número de chamadas fica registrado em config/uso_ia.
